# Evidence-grounded self-improvement

## Problem

Djimitflo has one real improvement path through OpenMythos,
GovernanceFeedbackLoopService and ExecutionEngine, but several parallel
services still record simulated scores or database logs as proven
modifications. The production feedback loop also promotes after one before/after
mean comparison, so model or judge variance can be mistaken for improvement.

The startup self-modification scan still uses route filename similarity even
though SelfCodeAnalysisService now provides route-service-test reachability.

## Outcome

1. GovernanceFeedbackLoopService becomes the production promotion authority.
2. Verification uses repeated paired baseline and candidate evaluations.
3. Promotion requires a confidence lower bound above the minimum effect and no
   regression on held-out previously passing cases.
4. Evaluation manifests persist exact run, case, model, corpus and decision
   evidence.
5. SelfModificationPipeline reuses SelfCodeAnalysisService.
6. Uncalled random experiment services are retired.
7. SEGML Level 5 no longer claims simulated database logging is self-modification.

## Non-goals

- No new orchestrator, judge framework, graph store or scheduler.
- No automatic merge or deployment.
- No production database mutation during implementation.
