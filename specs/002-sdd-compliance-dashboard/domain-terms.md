# Domain Terms — SDD Compliance Bounded Context

> Ubiquitous Language for the SDD Compliance BC.
> Every term below has exactly one meaning within this BC.

---

## Term: ComplianceReport

**Definition:**
A structured assessment of all feature specs against the 7-layer quality gates defined in the Constitution.

**Business Context:**
Generated by scanning all specs/ folders and evaluating each against L1-L7 layers. Can be exported as JSON or CSV.

**Invariants (EARS):**
- THE ComplianceReport SHALL include all feature specs in specs/
- WHEN a spec is missing layers THEN the report SHALL highlight them

**Related Terms:**
QualityGate, FeatureSpec

**Aliases to AVOID:**
Report, Audit, Assessment, DashboardData

---

## Term: QualityGate

**Definition:**
A specific information layer (L1-L7) that a feature spec must contain to be compliant.

**Business Context:**
L1 (Language Precision), L2 (Negative Requirements), L3 (Measurable Criteria), L4 (Hard Constraints), L5 (Codebase Anchoring), L6 (Edge Cases), L7 (Verified Library Specs).

**Invariants (EARS):**
- THE QualityGate SHALL be evaluable mechanically (CRITICAL layers)
- WHEN a spec fails L1, L3, or L6 THEN the gate SHALL block

**Related Terms:**
ComplianceReport, FeatureSpec

**Aliases to AVOID:**
Gate, Layer, Requirement, Check

---

## Term: FeatureSpec

**Definition:**
A single feature specification document in the specs/ folder, evaluated for compliance.

**Business Context:**
Each feature spec is a markdown document with user stories, requirements, and acceptance criteria.

**Invariants (EARS):**
- THE FeatureSpec SHALL have a unique name
- WHEN evaluated THEN the FeatureSpec SHALL receive a compliance score

**Related Terms:**
ComplianceReport, QualityGate

**Aliases to AVOID:**
Spec, Document, Feature, Ticket
