## 1. The reference paper: what it establishes, and what it does not

**Source.** arXiv:2610.29458v1 (submitted 21-10-2026), Bai, Song, Hao, Tao, Yang, Dai, Zhao, Wen, "Harness Scaling for
Generalizable Agentic Reinforcement Learning". I fetched the PDF and read it in full, including the appendices.

### 1a. What it establishes (FACT, within its own setting)

**Setup.**
- The harness is factorised into five components: system prompt **S**, tool interface **T**, observation **O**, context
  management **C** and workflow **W**.
- Each component has 3 realisations, which gives H = 3⁵ = 243 configurations. The realisations were generated by an LLM
  (Opus-4.7) under a "change only this component" constraint (App. A, Table 5).
- Training uses a strength-2 orthogonal array of **18 configurations** (every pair of component levels appears twice; Rao
  bound N ≥ 11 and N = 9λ → N = 18).
- Each task gets **K = 2** structurally nearby harnesses: one anchor plus its nearest neighbour by Hamming distance.

**Training and evaluation.**
- Policies are trained with RL (GRPO, PPO) on Qwen3-4B and Qwen3-30B-A3B over ClawGym-Task (13.5 k tasks), for 300 steps.
- Evaluation covers 18 held-out in-space configurations, plus Claude Code and OpenClaw as unseen black-box harnesses.

**Results.**

| Claim | Number (Pass@1, mean of 3 eval runs) |
|---|---|
| In-space gain vs single-harness RL, average over 3 benchmarks | +9.80 (4B GRPO), +3.57 (4B PPO), +5.21 (30B GRPO), +4.90 (30B PPO) |
| Transfer to Claude Code vs black-box SFT / RL through OpenClaw | 37.22 vs 35.08 / 33.38 (4B); 41.20 vs 38.08 / 36.28 (30B) |
| Structure matters | structured-18 > random-18 > first-order-3 > single; the full 243 (which includes the eval configs) is below structured-18 at a fixed budget |
| Per-task diversity | K = 2 > K = 1 > single; K = 2 beats a Repeat-2 control; K = 4 gives no further gain |
| Locality-aware vs random assignment | random assignment loses 1.2–3.0 points |
| Base harness preserved | −0.19 on the base harness vs +10.48 in-space (30B GRPO, ClawGym) |

### 1b. Limits of that evidence (FACT from the text, INFERENCE on the consequence)

- **No confidence intervals and no training-seed variance** are reported. Means are over 3 evaluation runs. Single-digit
  gains have unknown sampling error. **UNKNOWN:** how many training seeds were run.
- The behavioural analysis (state tracking, error recovery, …) is scored by an **LLM judge** (GPT-5.4, App. D). By this
  directive's rules that is not independent evidence. The Pass@1 results are benchmark-scored. Some benchmarks use a model
  judge for rubric items (App. C.2).
- The harness realisations are synthetic perturbations: aliases, distractor tools, metadata noise, compaction, plan-first.
  They are not real production harness differences.
- The claim is about **training** policies through diverse harnesses. Djimitflo trains no model: G6 is gated, not started,
  and out of scope here. **Nothing in the paper shows that inference-time harness selection, or prompt/genome evolution,
  generalises.**

### 1c. Djimitflo-specific hypotheses suggested by the paper (HYPOTHESIS, all untested here)

- **H-HS1.** Djimitflo maker outcomes are harness-sensitive: success changes across S/C/W at fixed model and task.
  TG-001 r2 points that way but is inconclusive: A−B +0.158 [−0.128, 0.422].
- **H-HS2.** The gym → prod gap (mined proxy 0.867 vs prod gate 0.311) is mainly a harness and evaluation-contract
  difference, not a model difference.
- **H-HS3.** A ranking of configurations learned on a structured subset predicts unseen combinations. That is additivity:
  low-order factorial structure is enough.
- **H-HS4 (only relevant if G6 training is ever approved).** Fine-tuning the local maker through a strength-2 harness set
  would transfer to the prod remote path better than fine-tuning through the gym harness alone.

## 3. Protocol HF-001: separating model, harness, interaction and generalisation

Design only; nothing is built. It needs a pre-registration with a committed sha before the first scored attempt, like
SEC-F1 and MFR-001.

### 3a. Question

At fixed task semantics, how much of the variance in maker success and graded quality comes from:
- the model (M);
- each harness component (S, O, C, W);
- the M × harness interaction;

and does a configuration ranking found on one task family hold on an unseen family and on unseen combinations?

### 3b. Factors (all runnable on the workstation with existing parts; 0 cloud tokens)

| Factor | Level 0 | Level 1 | Level 2 | Built from |
|---|---|---|---|---|
| S | gym goal (TG arm A renderer) | prod `LOOP_WORK.md` (TG arm B renderer) | structured minimal (TG arm D) | `tg-001.ts` frozen renderers. **Read-only reuse; the file itself is not modified** |
| O | no pre-run observation | failing-test report from a pre-run (exit code, failing test names, 1 200-char tail, as #716) | the same report plus the target's type-check errors | harness wrapper (new script under `scripts/hf-001/`) |
| C | one-line flattened (#609, prod remote) | multi-line | multi-line + prod control context (memory rules + K1 examples as production would select them) | existing `renderWorkAssignment` path |
| W | `--max-steps 40`, 900 s | `--max-steps 60`, 900 s (prod remote budget) | 60 + "state a plan, re-run the target every 3 edits" | atomic-agent CLI flags + prompt line |
| M | qwen38-27b (MFR's served model) | second router model (operator picks one: qwen36-a3b or gpt-oss-120b) | — | llama-router |

- **T** stays fixed at atomic-agent 0.6.5. It cannot vary without a second harness at fixed model, so it is reported as NOT
  TESTED.
- Using a strength-2 array for S, O, C, W gives **L9 (3⁴): 9 configurations**. Crossed with M (2 levels) that is 18 cells.
- This is the same coverage logic as the paper, applied to evaluation, not training.

### 3c. Tasks and units

- **Unit.** (task, configuration) is one attempt. Task is the block. The scoring oracle, prod gates (`GYM_PROD_GATES` set),
  base commit and target are identical across cells (the TG-001 rule).
- **Task set.** 20 failure-derived `write_test` tasks (graded by `mutant_kill`) plus 20 mined repair tasks.
  - Seeded and frozen.
  - None may be in any holdout epoch, a TG-001 set or a trial (`holdoutExclusions`).
  - HF tasks are then added to the exclusion list, so later holdouts stay clean.
- **Held-out for generalisation.**
  1. **Task family:** fit the configuration ranking on `write_test`, test it on `mined`, and the reverse.
  2. **Unseen combinations:** 3 full configurations outside the L9, chosen before data. Predict them from the additive
     main-effect model, then run them (H-HS3).
  3. **Environment (later):** the same 9 configurations on the second repository once its token exists (G1.1). Until then
     this item is NOT TESTED.

### 3d. Endpoints and analysis (pre-registered)

**Endpoints.**
- **Primary.** Pass under prod gates (binary).
- **Co-primary (write_test only).** Graded kill share on 3 fresh held-out mutants per task. These mutants are never shown,
  because the MFR leak rules apply.
- **Secondary.** Wall time; termination class; diff size; the TG-001 failure categories.
- Telemetry the agent does not report stays null. It is never recorded as 0.

**Model.** A mixed-effects logistic model (task random intercept) with fixed effects M, S, O, C, W and M×S, M×O, M×C, M×W.
The graded endpoint uses the linear analogue.

**What is reported.**
- Main effects with 95 % CIs (task-cluster bootstrap).
- The variance share of task, M, harness components and M×harness.
- The rank correlation of the 9 configuration means between task families.
- The prediction error on the 3 held-out configurations.

**Decision rules, frozen before data.**

| Finding | Rule | Consequence |
|---|---|---|
| A harness component matters | main-effect CI excludes 0 and \|effect\| ≥ 10 pt (pass) or ≥ 0.10 (graded) | that component becomes a controlled factor in every later species or genome comparison |
| Model × harness interaction matters | interaction LR test p < 0.05 **and** the best configuration differs between models | species must be compared at their own best harness; a species verdict at one harness is invalid |
| Generalisation holds | between-family Spearman ρ ≥ 0.6 and held-out prediction error ≤ 10 pt | a harness change selected in the gym may be proposed for prod (operator decision, shadow first) |
| Otherwise | — | gym-selected harness changes are not transferable; NE entry |

### 3e. Power and budget

- **Stage A (M fixed, 9 configurations × 40 tasks = 360 attempts).** Each factor level pools 3 configurations × 40 tasks =
  120 attempts. **INFERENCE:** that gives an MDE for a main effect of ≈ 12–15 pt on pass (paired by task, p ≈ 0.4–0.6) and
  ≈ 0.10 on graded (SD 0.35, n 60 per level on the write_test half).
- **Interactions.** The 2-df M × component interactions need roughly 4× the n per cell for the same resolution, so only
  large reversals are detectable. The rule above already requires a reversal.
- **Budget.**
  - GPU: 9.6 min per maker attempt on the workstation (MFR: 12.08 GPU-h for 80 runs, upper bound). Stage A is ≈ 58 GPU-h;
    Stage B (second model, + 360) is ≈ 58 GPU-h more.
  - Scoring is CPU only.
  - 0 cloud tokens. Energy ≈ 0.3–0.45 kW under load (PLAN E), so about 20–25 kWh per stage. € UNKNOWN: `workstation_kwh_eur`
    is null.
- **Throughput.** The harness yields to prod remote maker jobs, as MFR did. Stage A is about 4–6 days with the GPU in use 50 %
  of the time.

### 3f. Collision rules

- **Genome trials on epoch 1 share llama-router.** Stage B swaps the served model, which would contaminate a running trial,
  and the gym does not record the served model (file 2). **Stage B runs only after the epoch-1 trial settles.** Stage A
  keeps the model that the gym serves.
- **TG-001 (`stop_by` 18-11).** Its registered next step (40 vs 60 max-steps) is W0 vs W1 here. Proposal for the operator:
  close TG-001 INCONCLUSIVE at 20 tasks and fold its next step into HF-001. That avoids two experiments on one gym.
- **Oracle-population experiments** (ACE, STE, MAKER-DEPS, X1, F2, memory holdout): no collision, because HF-001 is offline
  and uses no prod goals or WIP slot.
- **The gym daily cap (40)** is not consumed. HF attempts run under their own label, like MFR (`djimitflo-gym-host=hf-001`).

## 4. Co-evolution rules (when harness and genomes both change)

1. **Alternate, never simultaneous.** While a genome trial runs, the harness (M, H, worker, gates) is frozen. Record the
   worker hash and served model per attempt and refuse a pair whose two attempts differ (file 3, H9).
2. **A harness change re-baselines the parent.** After any harness change, the parent genome re-runs its deciding set
   before any mutant comparison. The epoch-1 trial violates this today: 21 of 35 parent attempts predate the 22-10 D9
   runner change (file 6, E0).
3. **Harness variants are written by builders and reviewed. They are never produced by a model.** R (gates, scope, auth) is
   never a factor.
4. **Select harness changes on a task set disjoint from every genome holdout.** Otherwise harness selection consumes the
   holdout that genome selection depends on.
5. **Generalisation, not in-sample fit, decides.** A configuration is adopted only on held-out family/combination evidence
   (§3d). This is the part of the paper's method that does transfer to inference-time selection: structured coverage plus
   held-out configurations.
