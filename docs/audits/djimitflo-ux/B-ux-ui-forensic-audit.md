## Accessibility, keyboard and responsive evidence

Source includes skip-to-content, main landmark, navigation aria-current, labeled inputs/mobile drawer, and tab semantics. Native keyboard address navigation worked; browser filters and tabs worked through accessibility targets. This does **not** establish full keyboard-only task completion or screen-reader quality. Fixed summary/card layouts visibly overflow at the inspected desktop size. Sequential focus count on large decision/tool tables was not measured; likely load is a hypothesis, not a timed user finding. Contrast, zoom 200%, touch, reduced motion, focus restoration after route changes and narrow viewports require isolated browser tests. Prioritize readable identifiers, programmatic filter names and non-color state text over cosmetic redesign.
