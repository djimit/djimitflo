# Controlled experiment proposals

These are specifications, not launched trials. Current WIP six includes two explicit grandfathered exceptions, counted four under the guard. No additional production experiments start until current registered decisions/authorized amendments permit capacity. Preserve frozen TG/ACE/STE/memory contexts; required operator authorization for protected protocols is not replaced by this audit. No promotion follows a favorable interim point estimate.

## Shared reproducibility and decision contract

Use existing experiment registry/arm assignment/evidence/ledger and runtime adapters. Record immutable protocol/task/corpus/evaluator version, repo/base artifact, exact intervention and content/script hash, runtime/adapter/model/policy versions, tools/permissions, environment/dependencies, seed/order, assignment and actual delivery, retry/timeout/budget, raw result/evidence and exclusion reason. Separate all-assigned ITT, per-protocol and infrastructure-censored analyses. Randomize/counterbalance order; cluster repeated tasks/agents appropriately. Independent evaluators must not see arm identity or use their own answer as ground truth. Held-out tasks never feed candidate generation before decisions.

Primary practical effect, safety/quality non-inferiority, latency/cost budgets, alpha/multiplicity, sample/stopping and promotion criteria must be fixed before scoring. Report effect+CI, denominators, missingness, all failures and negative results. A failed equivalence/superiority test is insufficient evidence, not no effect. Infrastructure retries do not create extra independent samples. Terminal decision preserves cohort/config and uncertainty; adoption requires permitted promotion plus replication/survival, not only significance.

Planning approximation for paired binary outcomes: required pairs≈(z_.975+z_.8)^2×discordance/Δ². At assumed discordance .40 and minimum relevant absolute gain .15 this is≈140 pairs for80%power; actual paired exact-test power, losses, clustering/multiplicity can require more. This is a planning assumption to validate with a blinded pilot, **not** a power guarantee or retroactive target for existing trials. Continuous costs/latencies use paired differences/ratios and task-cluster bootstrap intervals; don't average per-run ratios into fleet efficiency.

## E1 · Exact-version cross-runtime skill transfer

**Hypothesis:** one already existing validated reusable skill improves independent task success by≥15pp versus the same receiving agent without it, without unacceptable safety/resource regressions. **Baseline/control:** identical runtime/model/tools/budget, current approved instructions and mandatory checks; no candidate package. **Intervention:** one exact package+script/manifest version through existing adapter, isolated environment, no silent changes elsewhere. Evaluate each receiving runtime (for example Hermes/OpenClaw) separately before pooled transfer claims.

**Primary:** independent held-out task success/quality; secondary latency,tokens/energy where measured, tool errors, correction burden, actual skill-delivery adherence. **Sample:** blinded feasibility pilot20 pairs checks execution/label validity only; confirmatory planning≈140independent taskpairs per receiving domain under assumptions above, exact power/familywise correction before registration. Repeated same-task versions are clustered, not extra tasks. **Confounders:** package compatibility, model/hardware, prior task exposure, instruction length, unsafe tool scope, caching/order and environment changes. **Stop:** any safety boundary violation or predefined budget/invalid-delivery threshold; futility/harm looks only if preregistered. **Promote:** compatible admission, meaningful positive CI lower bound under chosen test, no guardrail regression, independent fresh-domain replication and14/30d survival. **Regression:** repeat same controlled suite on later version; revert only through existing authorized lifecycle. No bulk sync/activation during audit.

## E2 · Swarm versus simpler execution

**Hypothesis:** existing delegation/sibling mechanism improves independent quality at the same total budget, or achieves non-inferior quality with materially lower latency/cost. Select exactly one primary objective; do not choose after results. **Control:** single maker with the same mandatory checker/security/authorization. **Intervention:** existing approved multi-maker/delegation option; total tokens/walltime/tool privileges matched. A “single agent” control must not remove safety checks.

**Primary:** task-level paired independently scored success; secondary p50/p95latency,total resource, duplicate tool calls, coordination failures, delegated-task accuracy, recovery, human corrections. **Sample:**20pair feasibility pilot then planning≈140 pairs for15pp/.4discordance, tasks stratified by complexity and failure class; confirm exact power and model/runtime interactions. Current observational133single/69multi completions are not randomized comparators or power evidence. **Confounders:** sibling selection on difficult tasks, retry count, model mix, shared memory/candidate leakage, parallel hardware, cache and budget accounting. **Stop:** quota/safety/harm bounds, fixed sample/deadline with insufficient result if underpowered. **Promote:** practically meaningful prespecified primary benefit, safety and cost constraints met, independent held-out replication; no “more agents” criterion. No live launch while WIP frozen.

## E3 · Memory/retrieval value and temporal validity

**Hypothesis:** validated retrieval/rules improve independent outcomes versus withheld context, with bounded overhead and no obsolete/conflicting evidence harm. **Control/intervention:** preserve current memory/ACE experiments; next revision uses same model/tasks/tools, sealed source/hash/time metadata, explicit on/off delivery. Do not change current rule selection to test this informally.

**Offline quality baseline:** independently annotate query→relevant evidence on a held-out versioned corpus, including outdated/conflicting/no-answer cases; compute precision/recall/nDCG only with valid labels.50query pilot establishes annotation agreement and failure modes, not a promotion decision. If estimating a proportion with worst-case±5pp95% precision,≈385independent queries before clustering/corpus effects; calculate final requirements for chosen metric. Downstream paired-task effect needs its own power (≈140 pairs under common planning assumption, not interchangeable with retrieval-query n). **Outcomes:** task success/faithfulness, unsupported claims, stale/contradiction exposure, retrieval latency/context tokens and measured cost; relevance alone is secondary evidence.

**Confounders:** adaptive rule popularity, task selection, contaminated corpus, missing attribution, current-status censoring and overlapping ACE/STE treatments. **Stop/promotion:** registered deadline/harm bound, meaningful independent downstream gain with uncertainty and no stale-evidence regressions; absence of gain does not automatically authorize deleting memory. Retention/sensitivity boundaries unchanged.

## E4 · Diagnostic journey usability

**Hypothesis:** truthful metrics/contextual links reduce diagnosis time/actions while maintaining or improving correct answers. **Baseline:** current routes and frozen incident/evidence fixture. **Intervention:** smallest implemented L6-01/03/04/07/12 changes; same underlying evidence. **Control:** current experience, counterbalanced within-operator task order; equivalent scenarios avoid learning the same answer. **Outcomes:** correct diagnosis/action, transitions/context switches/dead ends, elapsed time, keyboard completion and confidence calibration. **Sample:**8representative operators×7journeys is a pilot (56 task observations clustered withinoperators); report paired descriptive CIs and failures, no universal population claim. Use pilot variability/effect to power a later study if costly redesign decision depends on it. **Stop:** unrecoverable access/focus/data-disclosure defect. **Accept:** no loss of task correctness/accessibility, fewer dead ends and prespecified practical friction improvement; no imposed target seconds without baseline measurement.

## E5 · Gym information per resource

**Hypothesis:** existing headroom/epoch/dedup logic allocates evaluation effort to more decision-informative independent tasks without reducing real-defect detection. **Baseline:** retained evaluation logs/production-gate results; **control:** current permitted scheduler; **intervention:** replay-only selection policy first, never alter frozen live task/arm membership. **Primary:** independently distinguishable candidate decisions per measured job/resource under valid error control; secondary parent failures/discordance, production gate agreement, task freshness and detected regressions. **Sample:** replay all eligible retained tasks with explicit missingness; no power claim where no counterfactual outcomes were recorded. A new randomized block comparison requires independently powered tasks and approved WIP capacity. **Confounders:** proxy reward gaming, task reuse, ceiling effects, changing evaluator/model and missing resource fields. **Stop/promote:** no automatic promotion from replay; require fresh production-gated test/replication and no blind spots. Use current gym infrastructure, not another benchmark service.

Run order after current decision closure: passive usability/metadata verification first; then one skill or retrieval experiment selected for expected operational value; swarm and scheduling trials only when resource/provenance coverage can evaluate them. Record negative outcomes and prune only with explicit authority and measured replacement risk.
