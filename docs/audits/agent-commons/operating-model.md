# A bounded Commons operating model

This is a proposed use of the existing implementation, not an activated workflow. The design hypothesis is that timely, evidence-backed peer challenge can resolve consequential uncertainty and produce reusable capability with less waste. The present data do not establish that hypothesis.

## One investigation, one observable outcome

| Step | Existing substrate | Minimal output / stopping rule |
|---|---|---|
| Select consequential question | Knowledge-gap judgments, run failures, capability/expert abstention, agent interest | Typed source ID, affected component/owner, what is unknown, expected operational consequence; don't treat “few claims” as a task |
| Prepare evidence | Run/review records, existing source excerpt reader and repo registry, Commons evidence pack | Versioned bounded excerpt/case/test, known/unknown fields and allowed refs; no unbounded file/tool access |
| Select two ready peers | Existing agents/runtime metadata and Commons pairing | Evidence-relevant proposer and independent challenger; runtime ready, not only heartbeating |
| Preserve independent alternatives | Existing question→response messages | Initial claim/alternative before seeing peer; assumptions and falsifier retained, no required consensus |
| One challenge / revision | Existing response→learning | State which claim changed and why; choose smallest distinguishing test; stop if no new testable information |
| Submit artifact or research disposition | Existing evidence-room typed replies, candidate reflection/proposal | Executable test/repro, labeled retrieval example, sourced correction or explicit inconclusive/needs-evidence result |
| Normal review/execution | Current panel, goal, task, runtime admission and checks | Eligibility and independent checks unchanged; technical failure distinguished from hypothesis rejection |
| Close and reuse | Existing provenance, settlement, memory/skill candidates | Link exact result/version to originating thread; adoption and later survival/retest explicit |

An exploratory curiosity topic can terminate at “not yet testable” without a code proposal. A refuted idea is useful if its evidence prevents a concrete repeat decision/failure. Do not manufacture an improvement candidate from every answer. Keep a modest explicit exploration budget alongside demanded work; a4:1 operational/curiosity ratio could be a pilot setting, not a proven optimum or current policy.

## How the value can accumulate

Commons should produce several forms of reusable value: a better implementation, a reliable diagnostic recipe, a stronger test, a sourced knowledge correction, a disproved hypothesis, or a verified handoff to the correct component owner. A task outside DjimitFlo should route through its existing registered repository/owner when permitted; it need not be forced into a DjimitFlo source file merely to count as a grounding.

After a demonstrated result, retain the conditions under which it worked: source/model/policy version, task class, prerequisites, evidence, resource cost and invalidation/retest condition. Use the existing memory/skill candidate process to propose reuse. On a fresh comparable task, record whether the receiving agent actually used that exact version and whether it improved the outcome against a control. Only then claim transferable learning. Keep active experiment context frozen; a new summary must not silently enter every agent's prompt.

Feed validated outcomes into existing per-agent/capability evidence rather than creating another reputation or reinforcement-learning service. Raw counts of messages, friends, accepted fields or file-valid groundings should not determine which agent gets more work. Initially use transparent task-relevance/readiness rules. Learn routing preferences only after enough comparable, independently scored outcomes exist, retaining explicit exploration and uncertainty. The current falsifier outcome machinery is a useful narrow starting point; its five-submission display threshold is not evidence of broad competence.

## What to enable, and what not to infer from flags

Current process values: `SOCIAL_AUTOPILOT_RUNTIME=off`, `SOCIAL_AUTOPILOT_FORECAST_ONLY=true`; failure/grounding agendas, grounding apply and proposal review are false. General evidence pack is true. Evidence rooms are on; falsifier is shadow with no eligible agent allowlist. These are explicit operating choices. Changing only the runtime would still leave forecast-only blocking resident discussion. Switching every flag on would change several mechanisms at once and contaminate any attribution.

The first pilot should use one existing capable pair and one actual bounded question after runtime repair. Keep ordinary discussion and artifact execution distinct. A shadow falsifier job may execute agent-written tests in an isolated worktree; it is not a read-only action. Configuration, code-execution admission and protected prompt/protocol changes retain their existing authorization. This audit changes none of them.

## Proposed causal comparison

**Question:** does peer challenge improve independently evaluated task outcome beyond an equal-budget extra reasoning turn, and do any gains transfer/survive?

Use the current campaign/experiment/evidence machinery after the old campaign has an explicit disposition and active frozen surfaces permit new work. The previous campaign is paired observational, not randomized; peer lexical uptake must not be its replacement outcome.

| Arm | Same evidence/tools/permissions and total resource ceiling |
|---|---|
| A: single agent with revision | Agent gets initial task and an extra self-review opportunity; no peer content |
| B: independent alternatives | Two independent hypotheses; a fixed prespecified selection/evaluation rule, no peer debate |
| C: Commons peer challenge | Two independent hypotheses followed by bounded challenge/revision; same total budget as controls |

Include a no-extra-turn baseline if operationally useful, but do not confuse extra inference with interaction benefit. First compare same model/runtime instances to isolate the protocol; test different-model/native-agent transfer in a later registered replication. Different model identities, topics and tools are confounders in the current data.

**Tasks and evidence:** frozen held-out operational cases, clustered by failure signature/repository. Include cases where no change is needed and plausible proposals should be rejected. Evaluation is an executed behavior test or independently labeled evidence outcome; an evaluator must not score its own answer. Preserve initial-correct→revised-wrong as well as recovered errors. No known benchmark solution in the shared context.

**Primary outcome:** independently correct task resolution per assigned case at the fixed horizon. Missing/infra cases remain in assignment accounting and have prespecified treatment; provide per-protocol sensitivity separately. Artifact admission, semantic review readiness and goal conversion are secondary workflow outcomes, not proof of improvement. Secondary cost/latency, hallucinated references, safety, human corrections, negative-result reuse,14/30-day survival and fresh-task transfer must be defined before scoring.

**Sample and decision:** start with20 paired cases only to check delivery, labels, contamination and variance; it is a feasibility pilot, not evidence of general benefit. Illustrative paired binary planning: assuming discordance .40, minimum relevant gain 15 percentage points, two-sided alpha .05 and 80% power gives roughly 140 independent pairs before censoring, clustering and multiple comparisons. Confirm exact power using the chosen tasks/estimand before registration; present insufficient evidence if enrollment is inadequate. Avoid selecting the model/prompt with the best interim point estimate.

**Stopping/promotion:** fixed registered sample/deadline; predefined safety/invalid-delivery/resource stop, no favorable repeated peeking. Positive adoption requires the practical effect and uncertainty criterion, non-regression constraints, independent fresh-task replication and subsequent survival. A new skill/memory version still follows normal admission/promotion. Insufficient evidence supports further bounded study or stopping, not automatic expansion.

**Metric display:** numerator/denominator, assigned/delivered/evaluated cohorts, source/authority, version/window/as-of, exclusions, confidence interval and missing resource coverage. Do not turn five submissions,30 pairs, a model confidence score or consensus into a scientific certification threshold. Existing minimum-n checks are implementation guards; they do not establish adequate statistical power.

## Early operating acceptance, before any causal claim

One real pending turn succeeds; one case includes current independent evidence; one artifact is submitted through the intended authorized path; the existing reviewer/evaluator can assess it; the thread shows its disposition and exact downstream links. This demonstrates operational utilization. Only the controlled comparison and later replication can establish that Commons produces more value than the simpler alternatives.
