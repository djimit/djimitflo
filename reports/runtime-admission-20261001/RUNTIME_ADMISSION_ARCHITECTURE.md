# Runtime admission: architecture

## Order, as the code enforces it

```
Task ─► loop pause / agent availability / runtime governance (agent)
     ─► executor lookup (REGISTERED)                         execution-engine.ts executeTask
     ─► RUNTIME ADMISSION  (ADMITTED: runtime@version)       admitRuntime → checkAdmission
     ─► risk classifier → policy → governance gate → approval (ELIGIBLE_FOR_TASK)
     ─► capacity wait → startExecutionAttempt
          └─ every attempt and fallback: policy re-check + RUNTIME ADMISSION again
     ─► Executor ─► Evidence (diff, checks, events; runtime logs are inputs only)
```

Admission sits *before* policy rather than after it, which differs from the order in the prompt. Admission is a property of runtime@version and does not depend on the task. Every check must pass, so the order doesn't change the outcome. Denying first spends no risk classification or approval on a runtime that may not run, and it never creates an approval for one.

The four states:

| State | Meaning | Where it lives |
|---|---|---|
| REGISTERED | `registerExecutor` | engine map |
| AVAILABLE | the binary answers the probe | `runtime_contract_probes` (RuntimeCommandService) |
| ADMITTED | a ledger record whose decision is executable, unexpired and matches the version | `execution/runtime-admission.ts` |
| ELIGIBLE_FOR_TASK | policy, governance and approval passed for this task | engine, unchanged |

## Contract (`RuntimeAdmissionAssessment`)

- **Identity:** `runtime_id`, `runtime_version` (null only for a legacy record), `artifact_sha256?`, `source_revision`, `assessment_timestamp`, `assessed_by`.
- **Gates:** 8 gates, each `{status PASS|FAIL|NOT_PROVEN, evidence_refs[], note}`.
- **Authority:** 8 authorities, each `DJIMITFLO|RUNTIME|SHARED|UNKNOWN`.
- **Children and capability:** `child_agents` (`NONE|DJIMITFLO_GATED|RUNTIME_INTERNAL|UNKNOWN`) and `capability_gap` (`PROVEN|INCUMBENT|NONE|NOT_PROVEN` with refs).
- **Conditions and status:** `conditions[]` and `legacy{reason, migration[]}`.
- **Lifetime:** `reassessment_triggers[]` and `expires_at`.
- **Not stored, derived:** `decision` and `blocked_reasons` are computed by `decide()`, so a record can't carry a decision that contradicts its own gates.

## Decision rules (`decide`, deterministic, no averaging)

1. **REJECT** when any of these holds; a legacy status cannot mask any of them:
   - licensing, reproducibility or supply_chain is FAIL;
   - any authority is RUNTIME or SHARED;
   - capability_gap is NONE;
   - `assessed_by` is the runtime itself.
2. **HOLD** (or LEGACY_ADMITTED when the record is an explicit legacy record) when any of these holds:
   - any gate is not PASS;
   - a PASS gate has no evidence refs (it counts as NOT_PROVEN);
   - any authority is UNKNOWN;
   - child_agents is RUNTIME_INTERNAL or UNKNOWN;
   - the gap is NOT_PROVEN or lacks evidence;
   - the version is not bound.
3. **CONDITIONAL** when everything passes and `conditions[]` is non-empty. Each condition must name the mechanism that enforces it.
4. **ADMIT** otherwise.

## Execution check (`checkAdmission`)

- **Deny when** any of these holds:
  - there is no record (RA-01);
  - the decision is not executable;
  - the record has expired (RA-12);
  - the observed version is known and differs from the pinned one (RA-03/RA-11);
  - a non-legacy record is bound to a version and none was observed.
- **Where the observed version comes from:** Djimitflo's own probe row, and only one written after this process started. A row from before an image change is ignored, never taken from the task or the runtime.
- **Several records per runtime:** the record matching the executing version decides.
- **Recording:** every decision is written as an `execution_events` row with `source: runtime-admission` and the record's content hash (`runtime@version#sha12`) (RA-16).

## Reassessment

- **When:** on the triggers listed in each record, and at expiry (legacy: 2026-12-31). Stall watch detector 6 reports `runtime_admission:<id>` 30 days before expiry.
- **How it is tested:** a version change is a drift deny (tested). A dependency or licence change requires a new record through PR review.

## Rollback

- **Operator switch:** `RUNTIME_ADMISSION_MODE=shadow` keeps recording every decision and stops blocking. This is a visible WARNING event, not a silent bypass.
- **Full revert:** revert the commit. There are no schema changes.
