# Runtime admission: analysis

Date 2026-10-01. Baseline: origin/main `47818d5b`, CI green. Work happened in a separate worktree; the user's checkout on `audit/fase5-close-loop` was not touched.

## Does runtime admission already exist? **PARTIALLY_EXISTS**

| Existing piece | What it does | Covers | Gap |
|---|---|---|---|
| `RuntimeCommandService.getRuntimeContract` (`services/runtime-command-service.ts`) | Probes the binary (`--version`, `--help` flags) and writes conformance checks plus a `contract_hash` to `runtime_contract_probes` | Part of G3 (structured output, cwd and headless flags), part of G6 (timeout/kill flag), availability, drift of CLI flags | It only says *can* it run. It holds no licence, reproducibility, authority, supply-chain, gap or gym evidence and no expiry. Only loop paths call it (`assertRuntimeAvailable`, worker manifests). The ExecutionEngine never does. |
| `ExecutionEngine` pre-dispatch (`execution/execution-engine.ts`) | Pause and agent checks → risk classifier → PolicyDecisionService → governance gate (tighten-only) → approval; `fallbackAdmitted` re-runs policy for fallbacks | Policy for the *task* | Any registered executor is implicitly trusted: "registered = admitted" |
| `RuntimeGovernanceService` | Behavioural monitoring of *agents* (baselines, circuit breaker, quarantine) | Agent behaviour after certification | Not about runtimes or artifacts |
| `ExecutionModePolicyService`, `CircuitBreakerService`, `FallbackChainService` | Per-mode evidence and gates; executor health; fallback order | Mode policy, health | A fallback could pick any registered kind |
| `NestedSpawnService` | Djimitflo-visible children: depth budget (default 0), tighter grants, cycle guard, capability routing | RA-10 for children Djimitflo spawns | Children *inside* a runtime (for example opencode subagents) are invisible to it |
| Dockerfile pins | opencode 1.18.10, codex 0.146.0, claude-code 2.1.282 (npm); atomic 0.6.5 with sha256 in the repo | Part of G2/G8 | Not connected to any execution decision |
| OpenSpec / OpenWiki | No runtime-admission change or claim. `openwiki/` is generated by OpenWiki (repository convention: not hand-edited) | — | — |

## Decision: CREATE a small RuntimeAdmissionGate, enforced in the ExecutionEngine

- **Not an extension of RuntimeGovernanceService.** That service is about agent behaviour and listens to the event bus. Admission is a static, reviewed property of a runtime@version.
- **Not an extension of RuntimeContract.** The probe is runtime-reported evidence, an input to admission. Admission must not rest on runtime self-reporting, so the probe can only supply the *observed version*.
- **The smallest coherent design:**
  - one pure module, `execution/runtime-admission.ts` (contract, decision algebra, version matching, a ledger kept in git);
  - one engine method, `admitRuntime`, called at the executor-selection point and on every attempt, fallbacks included;
  - one stall detector for expiry.
- **No new table, route or service class.** The ledger lives in the repo, so a change of assessment goes through PR review. Git provides its integrity, the same choice P1 made for skill examples.

| any other kind (`custom`, `docker`, …) | UNKNOWN_RUNTIME, denied | — | — |

**No current third-party runtime reaches ADMIT under the strict contract.** That is a finding, not a defect. Network egress of CLI child processes is not scoped anywhere today; `OUTBOUND_DENY_HOSTS` guards only in-process fetch. The legacy status expires on 2026-12-31. The stall watch warns 30 days earlier.
