## Configuration and propagation

Persist on the existing task metadata:

```json
{
  "model": "gpt-6-astra",
  "reasoningEffort": "high",
  "codexSandbox": "workspace-write"
}
```

Dispatch the task with executor `codex`. ExecutionEngine validates and passes the selection to CodexExecutor. `reasoningEffort` accepts low/medium/high/xhigh/max; `codexSandbox` accepts read-only/workspace-write. No user input can choose danger-full-access through this new sandbox option. Existing explicit permission-bypass gates remain separate.

Operator defaults are `DJIMITFLO_CODEX_MODEL` and `DJIMITFLO_CODEX_REASONING_EFFORT`. Absent explicit settings, CLI defaults remain in effect. Task-start events record model/reasoning configuration; native command/tool events are surfaced and reported token usage reaches the execution result.

The actual browser execution fixture exposed a parser defect: ordinary stderr diagnostics permanently disabled stdout JSON parsing. The corrected adapter separates streams, recognizes each stdout JSON record independently, retains subsequent structured events after malformed lines, and installs listeners before starting a fast child. Oversized unfinished lines produce explicit evidence warnings. Structured command status, not words such as error in successful command output, determines command outcome. Wire-shaped regressions and actual child-cancellation tests cover this boundary; real browser reexecution is recorded separately.

The local browser fixture uses the existing server-owned `CODEX_BIN_PATH` seam with a temporary wrapper adding `--ignore-user-config --ephemeral` and explicit `workspace-write` when no narrower task sandbox is supplied. This is test configuration, not a global runtime default. Native sandbox enforcement and subscription authentication remain enabled. The official non-interactive guide documents explicit sandbox selection and config isolation. [OpenAI Docs](https://learn.chatgpt.com/docs/non-interactive-mode).

The existing runtime-readiness endpoint now recognizes Codex subscription login as well as API-key configuration. Readiness reports configuration evidence and never starts a worker. It is not model-account entitlement or end-to-end certification.

Executor environment is server-owned. The task HTTP API rejects caller-supplied `metadata.environment` and preserves internal nested-spawn settings on PATCH; it is not an API for arbitrary host CLI environment overrides.
